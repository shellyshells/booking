🧩 Design Patterns Implemented

This application demonstrates several Gang of Four (GoF) design patterns applied to a real-world room reservation system.

1️⃣

Singleton

Creational Pattern

Problem Solved:

Ensures only one instance of the Logger and Configuration Manager exists globally throughout the application.

Where Used:
  • LOGGER - Global logging system
  • CONFIG - Application configuration
🏭

Factory Method

Creational Pattern

Problem Solved:

Creates room objects dynamically based on type without exposing instantiation logic.

Where Used:
  • RoomFactoryManager - Room creation
  • Different factories for each room type
🌳

Composite

Structural Pattern

Problem Solved:

Treats individual rooms and groups of rooms uniformly for bulk operations.

Where Used:
  • RoomGroup - Grouping rooms by floor/building
  • Bulk reservations
🪶

Flyweight

Structural Pattern

Problem Solved:

Shares immutable room type information across many room instances, reducing memory usage.

Where Used:
  • RoomTypeInfo - Shared type metadata
  • Default equipment and rates
🎯

Strategy

Behavioral Pattern

Problem Solved:

Allows different validation rules for different user types (Standard, VIP, Admin).

Where Used:
  • StandardValidationStrategy
  • VipValidationStrategy
  • AdminValidationStrategy
👁️

Observer

Behavioral Pattern

Problem Solved:

Decouples event sources from handlers. Multiple observers react to reservation events.

Where Used:
  • EmailNotifier
  • AnalyticsTracker
  • AuditLogger
  • SlackNotifier
🔌

Adapter

Structural Pattern

Problem Solved:

Integrates with external calendar APIs without modifying core application code.

Where Used:
  • GoogleCalendarAdapter
  • OutlookCalendarAdapter
  • ICalAdapter
